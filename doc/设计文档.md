# MacToWindows 软件设计文档

**文档版本：** v1.0  
**状态：** 设计基线  
**目标平台：** macOS 13 及以上  
**目标架构：** Apple Silicon、Intel Universal Binary  
**实现语言：** Rust；macOS 平台适配使用 CoreGraphics/Core Foundation/AppKit FFI  
**产品类型：** 菜单栏常驻、系统级键鼠映射工具

---

## 1. 设计目标

MacToWindows 的目标是在 macOS 上建立一个安全、低延迟、可恢复的 Windows 输入语义层，让 Windows 用户继续使用熟悉的键盘和鼠标操作。

本设计文档解决以下问题：

1. 如何在 macOS 全局事件流中监听、过滤和注入键鼠事件。
2. 如何在 Rust 中建立可测试的规则引擎，而不把 macOS 细节扩散到业务代码。
3. 如何保证按键按下和释放严格配对，避免卡键、重复键和事件回环。
4. 如何在权限不足、事件 Tap 被系统关闭、注入失败或配置损坏时安全降级。
5. 如何让配置、用户界面、诊断和测试具备后续扩展到按应用、按设备规则的能力。

设计原则：

- **Fail-safe：** 无法确定如何处理时透传原始事件。
- **热路径无阻塞：** Event Tap 回调不执行文件、网络、日志落盘或 UI 操作。
- **纯逻辑可测试：** 规则匹配、修饰键状态机和配置校验尽量保持平台无关。
- **物理键优先：** 键盘映射基于物理 keycode 和左右修饰键，不基于已经布局转换后的字符。
- **单向事件流：** 原始事件只经过一次映射，生成事件带标记，避免递归处理。
- **可恢复：** 用户随时可以关闭映射并回到 macOS 原生输入。

## 2. 范围与约束

### 2.1 首版范围

- 全局键盘和鼠标事件映射。
- Windows 物理键位预设。
- 用户可编辑规则、导入和导出配置。
- 菜单栏启停、全局热键和紧急停用。
- 鼠标按钮、滚轮和拖拽状态映射。
- 独立常驻的纯文本剪贴板历史和 Win+V 浮动面板。
- Accessibility、Input Monitoring、Post Event 权限检查和引导。
- macOS 13+，Apple Silicon 与 Intel。

### 2.2 暂不支持

- 登录窗口、FileVault 解锁界面和其他系统安全界面。
- Secure Input 场景下的全部重映射保证。
- 游戏反作弊、虚拟机、远程桌面中的全部输入保证。
- 触控板手势、鼠标加速度曲线和复杂宏系统。
- 文本字符重排和死键重编码；输入源切换通过独立的 macOS Text Input Source Services 适配层实现。
- 剪贴板首版不保存图片、文件、富文本或密码来源信息。
- 需要 root 权限的 HID 层注入。

### 2.3 默认键位语义

首版预设按 Mac 键盘的物理位置对齐 Windows 键盘：

| Mac 物理按键 | 默认 Windows 语义 |
|---|---|
| 左 Control | Ctrl |
| 左 Option | Windows |
| 左 Command | Alt |
| 右侧对应修饰键 | 对应右侧 Windows 修饰键 |
| Fn / Globe | 透传 |
| 普通字符键 | 保持原物理 keycode |
| 媒体键 | 默认透传，可编辑 |

该预设必须通过配置表实现，不能将映射逻辑散落在代码中的多个 `match` 分支。后续可以新增“快捷键习惯”预设，例如 Command→Ctrl、Option→Alt。

## 3. 方案选型与架构决策

### 3.1 候选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| CoreGraphics `CGEventTap` + Rust FFI | 可全局监听、过滤和注入；事件字段完整；可控制生命周期 | FFI、权限、RunLoop 和 CF 对象管理复杂 | **采用** |
| `rdev`/`enigo` | 原型开发快，Rust 抽象较简单 | 全局抓取接口不稳定，事件字段和系统兼容性不足 | 仅用于原型验证 |
| Karabiner-Elements/虚拟 HID | 底层映射能力成熟 | 依赖外部软件、系统扩展和更重的安装流程 | 首版不采用 |

### 3.2 总体架构

```text
┌──────────────────────────────────────────────────────────┐
│                    MacToWindows App                      │
│                                                          │
│  Tauri 2 / 菜单栏 UI                                     │
│       │  IPC 命令与状态事件                              │
│       ▼                                                  │
│  Control Channel ───────► Event Runtime Thread           │
│                              │                           │
│                      CGEventTap + CFRunLoop              │
│                              │                           │
│                      Event Normalizer                    │
│                              │                           │
│                      Rule Engine                         │
│                              │                           │
│             Pass / Suppress / Emit                       │
│                              │                           │
│                    Event Injector                        │
└──────────────────────────────┼───────────────────────────┘
                               ▼
                         macOS Event Stream
```

### 3.3 UI 技术决策

首版采用 Tauri 2 作为菜单栏和配置界面容器：

- Rust 负责应用生命周期、权限、事件引擎和配置。
- WebView 负责配置表、规则编辑和诊断界面。
- 菜单栏采用 Tauri 的 tray 能力。
- `Info.plist` 设置 `LSUIElement=true`，不在 Dock 中显示主窗口图标。
- UI 只能通过命令通道修改事件运行时，不能直接访问 Event Tap。

如果后续需要完全原生 AppKit 界面，可以替换 UI 层，核心事件接口不变。

## 5. 运行时与线程模型

### 5.1 线程职责

#### UI 主线程

- Tauri WebView 和菜单栏生命周期。
- 接收用户配置操作。
- 展示权限、运行状态和错误。
- 不直接处理键鼠事件。

#### Event Runtime Thread

- 创建并持有 `CGEventTap`。
- 创建并运行 `CFRunLoop`。
- 持有可变的 `RuntimeState` 和按键状态机。
- 在回调中同步执行规则匹配。
- 根据 `Decision` 立即透传、抑制或注入事件。
- 处理 `tapDisabledByTimeout` 和 `tapDisabledByUserInput`。

#### Control/Diagnostics Thread

- 接收运行时状态事件。
- 处理异步日志和计数器。
- 读取权限状态。
- 执行配置文件读写和导入导出。

### 5.2 通信方式

UI 到 Event Runtime 使用有界命令通道：

```text
enum RuntimeCommand {
    Enable,
    Disable,
    ReplaceRules(CompiledRules),
    SetProfile(ProfileId),
    ReloadPermissions,
    ReleaseAll,
    Shutdown,
}
```

Event Runtime 到 UI 使用状态事件通道：

```text
enum RuntimeStatus {
    Disabled,
    Running,
    PermissionRequired(PermissionState),
    Degraded(DegradedReason),
    TapRestarting,
    Stopped,
}
```

配置修改流程为：

1. UI 提交原始配置。
2. 配置模块反序列化并校验。
3. 规则引擎编译为不可变 `CompiledRules`。
4. 编译成功后通过命令通道发送给 Event Runtime。
5. Event Runtime 在安全边界替换规则快照。
6. 编译失败时保留上一份有效规则，并返回精确错误位置。

热路径不使用全局可变锁。事件线程独占运行时状态，规则更新通过消息在事件线程完成切换。

## 6. 领域模型

### 6.1 事件模型

```rust
pub struct NormalizedEvent {
    pub source: DeviceSource,
    pub kind: EventKind,
    pub phase: EventPhase,
    pub code: PhysicalCode,
    pub modifiers: ModifierSet,
    pub location: Option<Point>,
    pub scroll: Option<ScrollDelta>,
    pub timestamp_ns: u64,
    pub app_context: Option<AppContext>,
    pub origin: EventOrigin,
}

pub enum EventKind {
    Keyboard,
    MouseButton,
    MouseMove,
    Scroll,
    FlagsChanged,
    TapLifecycle,
}

pub enum EventPhase {
    Down,
    Up,
    Repeat,
    Changed,
    Motion,
}

pub enum EventOrigin {
    Hardware,
    Injected { marker: u64 },
}
```

`PhysicalCode` 包含 macOS keycode、鼠标按钮编号和滚轮轴信息。字符值不作为默认匹配键。

### 6.2 动作模型

```rust
pub enum Decision {
    Pass,
    Suppress,
    Emit(Vec<OutputEvent>),
}

pub enum OutputEvent {
    Key { code: PhysicalCode, phase: EventPhase, modifiers: ModifierSet },
    MouseButton { button: MouseButton, phase: EventPhase },
    Scroll { delta_x: f64, delta_y: f64 },
    SystemShortcut(SystemShortcut),
}
```

`SystemShortcut` 只包含已验证的 macOS 等价动作，例如锁屏、应用切换和显示桌面。没有可靠等价动作时，不生成事件。

### 6.3 规则模型

```rust
pub struct Rule {
    pub id: String,
    pub enabled: bool,
    pub priority: i32,
    pub scope: RuleScope,
    pub trigger: Trigger,
    pub action: Action,
}

pub enum RuleScope {
    Global,
    App { bundle_id: String },
    Device { identifier: String },
}

pub enum Trigger {
    Key {
        code: PhysicalCode,
        modifiers: ModifierMatcher,
        phase: EventPhase,
    },
    MouseButton {
        button: MouseButton,
        phase: EventPhase,
    },
    Scroll {
        axis: ScrollAxis,
    },
}

pub enum Action {
    Pass,
    Suppress,
    Replace(Vec<OutputEvent>),
    InvertScroll,
}
```

### 6.4 规则匹配优先级

规则按照以下顺序选择：

1. 紧急停用热键。
2. 自注入事件标记过滤。
3. 映射总开关状态。
4. 应用范围规则。
5. 设备范围规则。
6. 精确组合键规则。
7. 规则优先级。
8. 配置文件中的稳定顺序。
9. 默认预设转换。
10. 原始事件透传。

相同范围、相同触发器和相同优先级的规则视为冲突，配置校验必须拒绝保存。

## 7. 键盘映射设计

### 7.1 处理阶段

单个硬件键盘事件按照以下阶段处理：

```text
CGEvent
  ↓
读取 keycode / flags / phase
  ↓
过滤自注入标记
  ↓
检查 panic hotkey
  ↓
检查运行模式和权限
  ↓
更新物理按键状态
  ↓
匹配精确规则
  ↓
应用默认修饰键转换
  ↓
生成输出事件
  ↓
更新逻辑按键状态
  ↓
透传或注入
```

### 7.2 修饰键状态机

必须同时维护：

- `physical_down`：当前物理按下的键。
- `logical_down`：已经注入给目标应用的键。
- `source_to_output`：物理 keycode 到输出 keycode 的映射。
- `repeat_state`：长按和自动重复状态。
- `pressed_at_generation`：每个按键按下时使用的规则版本。

释放事件必须使用按下时确定的输出映射，即使用户在中途修改规则。这样可以避免配置热更新导致释放事件找不到对应目标键。

切换模式或关闭应用时执行：

1. 停止接受新的映射事件。
2. 根据 `logical_down` 注入所有缺失的释放事件。
3. 清空物理和逻辑状态。
4. 再切换为透传或停止 Event Tap。

### 7.3 组合键处理

MVP 重点支持“修饰键集合 + 一个主键”的组合，例如 Ctrl+C、Alt+Tab、Win+L。

任意组合规则必须声明：

- 修饰键集合。
- 主键。
- 按下、释放或重复阶段。
- 是否抑制原始组合。
- 输出事件顺序。

输出事件必须先生成修饰键按下，再生成主键，释放顺序与输入顺序相反。多目标输出时需要引用计数，避免两个物理来源共享一个逻辑修饰键时提前释放。

### 7.4 字符和输入法

默认不根据字符匹配键盘规则。以下事件默认透传：

- 中文输入法组合状态。
- 死键。
- Unicode 文本事件。
- 当前键盘布局生成的字符事件。

这样可以避免键位映射破坏输入法和国际键盘布局。

输入源和大小写行为由平台动作处理：

- `Ctrl+Shift` 在当前启用输入源列表中循环选择下一个输入源。
- Caps Lock 使用 macOS 原生锁定状态。用户需要关闭“使用 Caps Lock 键切换到和切换自 ABC”，避免系统输入源快捷键抢占 Caps Lock。
- Apple Pinyin 下，独立短按 Shift 在当前拼音输入源与最近使用的 ASCII 输入源之间切换；Shift+字符、长按和鼠标组合保持透传。
- Text Input Source Services 只能在串行平台服务中调用，Event Tap 回调只读取快照并发送命令。

剪贴板服务由三个边界组成：

1. 纯 Rust 历史核心负责 50 条上限、重复项前移、字符数限制和 JSON 原子持久化。
2. macOS 适配层在独立线程中轮询 `NSPasteboard` 的 `changeCount`，只读取字符串类型，并提供前台 `NSRunningApplication` 的恢复。
3. Event Tap 只识别左 Option+V 并通过无阻塞 channel 通知 Tauri；浮动窗口显示、历史选择、剪贴板写回和 Command+V 注入都在后台 worker/主线程完成。

剪贴板历史文件位于 `~/Library/Application Support/MacToWindows/clipboard-history.json`。启动时只恢复历史，不主动采集已有剪贴板；损坏文件改名为 `.corrupt.<timestamp>` 后从空历史继续。选择历史产生的自身 `changeCount` 会被忽略，避免重复入库。

## 8. 鼠标映射设计

### 8.1 鼠标按钮

鼠标按钮规则使用物理按钮编号匹配。交换左右键时，按下和释放必须使用同一映射。

按钮状态机需要维护：

```text
physical_button_down
logical_button_down
source_button_to_output
```

拖拽期间不得因为规则刷新而改变目标按钮。关闭映射时必须先释放逻辑按钮，再恢复原生事件。

### 8.2 滚轮

- 垂直滚轮和水平滚轮分别处理。
- 反转滚动时只修改 delta 符号。
- 保留连续滚动事件的精度和时间戳。
- 不把滚轮转换成离散按键，除非用户明确配置。
- 鼠标移动和指针坐标默认透传。

### 8.3 触控板

首版不主动拦截触控板手势。无法可靠区分的手势事件必须透传，避免破坏系统手势、Mission Control 和应用内手势。

## 9. macOS Event Adapter

### 9.1 Event Tap

Event Runtime 使用 `CGEventTapCreate` 创建会话级 active filter：

- 监听 `keyDown`、`keyUp`、`flagsChanged`。
- 监听 `mouseDown`、`mouseUp`、`otherMouseDown`、`otherMouseUp`。
- 监听 `scrollWheel`。
- `mouseMoved` 和拖拽移动事件默认只透传。
- 监听 Tap 生命周期事件，处理被禁用和重启。

事件 Tap 回调必须：

- 不执行阻塞 I/O。
- 不直接更新 UI。
- 不触发 Rust unwind 穿过 C ABI；必要时使用 `catch_unwind`，捕获后返回 `Pass` 并将运行时切换到降级状态。
- 处理空事件、无效 keycode 和未知事件类型。

### 9.2 回调行为

```text
callback(event):
    if event carries self marker:
        return event

    if panic hotkey matches:
        disable mapping
        return original event or suppress according to hotkey policy

    if runtime is disabled or degraded:
        return event

    normalized = normalize(event)
    decision = engine.handle(normalized)

    match decision:
        Pass:
            return event
        Suppress:
            return null
        Emit(outputs):
            inject(outputs)
            if inject succeeds:
                return null
            else:
                mark degraded
                return event
```

### 9.3 事件注入与回环防护

每个生成事件都必须写入唯一标记，推荐使用 `CGEventSourceSetUserData` 或等价的事件元数据字段。

注入流程：

1. 创建目标 CGEvent。
2. 复制必要的 flags、时间戳、重复状态和拖拽状态。
3. 写入应用实例唯一 marker。
4. 通过 `CGEventTapPostEvent` 或 `CGEventPost` 注入。
5. 回调再次收到事件时，检测 marker 后直接放行，不再经过规则引擎。

如果注入失败，不得继续吞掉原始事件。

### 9.4 Event Tap 被禁用

监听以下系统事件：

- `tapDisabledByTimeout`。
- `tapDisabledByUserInput`。

处理策略：

1. 更新运行状态为 `TapRestarting`。
2. 记录错误计数和最近一次原因。
3. 在事件线程重新启用 Event Tap。
4. 若连续失败，进入 `Degraded`，停止拦截并提示用户。
5. 用户可以从菜单栏重新授权或重启事件服务。

退出时必须：

1. 发送 `ReleaseAll`。
2. 禁用 Event Tap。
3. 从 CFRunLoop 移除 source。
4. 释放 CFMachPort、CFRunLoopSource 和其他 CF 对象。
5. 关闭事件线程。

## 10. 权限管理

### 10.1 权限类型

运行前需要检查：

- Accessibility / 辅助功能访问。
- Input Monitoring / 输入监控或监听事件权限。
- Post Event / 发布事件权限。

权限名称和系统设置页面可能随 macOS 版本变化，代码不能依赖固定文案。

### 10.2 权限状态机

```text
Unknown
  ↓
Checking
  ├── Ready
  ├── NeedAccessibility
  ├── NeedListenEvent
  ├── NeedPostEvent
  └── PermissionError
```

只要任一必需权限缺失，运行时进入安全降级：

- 不拦截原始事件。
- 不注入替代事件。
- UI 显示缺失权限和打开系统设置按钮。
- 周期性重新检测权限。
- 权限恢复后允许用户手动启用映射。

### 10.3 首次启动流程

1. 展示用途、隐私说明和风险提示。
2. 检查所有权限。
3. 逐项引导用户打开系统设置。
4. 重新检测权限，不假设授权立即生效。
5. 运行键盘和鼠标测试。
6. 用户点击“启用 Windows 模式”后才开始拦截。

### 11.1 文件位置

### 11.3 读写与迁移

配置保存必须遵循：

1. 写入临时文件。
2. `fsync` 文件。
3. 对目录执行必要的同步。
4. 使用 rename 原子替换。
5. 保留上一份有效备份。

导入配置时：

- 校验 `schema_version`。
- 执行版本迁移。
- 逐条报告错误路径，例如 `profiles[0].rules[3].action`。
- 编译规则成功后才替换当前配置。
- 失败时保留旧配置并提供恢复按钮。

## 12. 配置校验与规则编译

规则编译阶段生成 `CompiledRules`，包含：

- 按事件类型索引的规则表。
- 按 scope 和优先级排序的候选规则。
- 预计算的修饰键转换表。
- 冲突和循环检测结果。
- 预设系统快捷键的已验证输出序列。

必须拒绝以下配置：

- 同一触发器存在相同优先级的不同动作。
- 规则引用不存在的 keycode、鼠标按钮或系统动作。
- 释放动作无法找到对应按下动作。
- 规则产生递归映射。
- 输出事件数量超过限制。
- 生成事件包含不可用或保留的事件类型。

MVP 建议限制单次映射输出不超过 16 个事件，最大映射深度为 1。

## 13. 状态与故障处理

### 13.1 应用状态

```text
Starting
  ↓
CheckingPermissions
  ├── ReadyDisabled
  ├── ReadyEnabled
  ├── PermissionRequired
  ├── Degraded
  └── Stopping
```

### 13.2 故障安全矩阵

| 故障 | 处理 | 用户可见信息 |
|---|---|---|
| 权限未授予 | 原始事件透传 | 缺少哪项权限及入口 |
| 权限被撤销 | 立即停用映射 | 权限状态变化 |
| Event Tap 创建失败 | 不启动拦截 | 创建失败原因 |
| Event Tap 被禁用 | 自动尝试重启 | 正在恢复或已降级 |
| 规则编译失败 | 保留旧配置 | 错误路径和原因 |
| 注入失败 | 放行原始事件 | 注入失败计数 |
| 运行时 panic | 捕获并降级透传 | 需要重启或报告 |
| 配置文件损坏 | 回滚备份 | 已恢复上次有效配置 |
| 应用退出 | release_all | 无需用户操作 |

## 15. 日志、诊断与隐私

默认日志不记录：

- 原始字符。
- 文本输入内容。
- 完整按键序列。
- 用户正在编辑的文档内容。

默认只记录：

- 应用启动和退出。
- 权限状态变化。
- Event Tap 生命周期。
- 规则编译错误。
- 注入失败次数。
- 事件类别计数。
- 回调延迟统计。

日志可以由用户关闭。诊断导出前需要明确提示将包含哪些元数据。

## 16. 性能设计

### 16.1 目标

- Event Tap 回调处理 P95 小于 5ms。
- 用户感知的端到端延迟小于 20ms。
- 空闲 CPU 小于 2%。
- 常驻内存小于 100MB。
- 普通配置下不产生每事件堆分配。

### 16.2 实现要求

- 事件线程持有规则和状态，不在热路径竞争锁。
- 规则在 UI 线程编译，在事件线程一次性替换。
- 日志使用无阻塞计数器和异步批量落盘。
- 事件对象使用小型栈结构或对象池，避免不必要的字符串创建。
- 诊断统计使用原子计数器。

## 20. 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| macOS 权限状态变化 | 无法监听或注入 | 启动检查、周期检查、降级透传 |
| Event Tap 被系统禁用 | 映射突然失效 | 监听禁用原因并自动重启 |
| 修饰键状态丢失 | 卡键或错误释放 | 物理/逻辑双状态机、release_all |
| 自注入事件回环 | CPU 占用和重复输入 | 唯一 marker、单次映射深度 |
| Secure Input | 部分应用不可用 | 明确兼容性边界并提示 |
| 配置热更新 | 按下和释放不匹配 | 按下时冻结映射版本 |
| FFI 内存管理 | 崩溃或资源泄漏 | 明确 CF 对象所有权并封装 RAII |
| 规则过多 | 延迟增加 | 编译索引、不可变快照、性能基准 |
| 系统快捷键无等价动作 | 用户误以为失效 | 显示“不支持/需自定义” |

## 21. 设计验收清单

在进入编码阶段前，必须确认：

- [ ] 事件线程能在回调内同步给出 Pass/Suppress/Emit。
- [ ] UI 不会直接操作 Event Tap。
- [ ] 规则更新不会在按键按下/释放之间切换映射。
- [ ] 权限不足和注入失败都会透传原始事件。
- [ ] 所有生成事件都有 marker。
- [ ] Event Tap 被禁用后有恢复或降级路径。
- [ ] 退出时会释放所有逻辑按键和鼠标按钮。
- [ ] 配置写入具有原子替换和备份回滚能力。
- [ ] 冲突、循环、非法输出在保存前被拒绝。
- [ ] 不记录原始字符和文本。
- [ ] 核心规则引擎可以脱离 macOS 适配层单独测试。
- [ ] 有真实 macOS 设备上的权限、布局、应用和睡眠唤醒测试计划。
