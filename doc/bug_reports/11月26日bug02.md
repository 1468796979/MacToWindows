## 详细发现

### BUG-01 · P1 · Caps Lock 可使全局映射降级

启用默认 Windows 预设，按住左 Command，再按 Caps Lock。原生适配把 Caps Lock 规范化为 `FlagsChanged / Changed`。规则引擎发现同一事件中的 Command 标志需要转换，会尝试生成 `Key(57, Changed)`。原生输出构建只接受 `Down`、`Up` 和 `Repeat`，返回 `InvalidEvent`，控制器随后进入 `Degraded`，其余快捷键停止转换。隔离验证覆盖了合成 CoreGraphics 对象、真实输出构建器，以及使用注入替身的真实控制器。观察到左 Option Down、Caps Lock 输出被拒、左 Option 清理 Up，控制器进入 `Degraded`。修复时应保留 Caps Lock 的原生锁定事件，并在需要时只改写相关修饰标志。 [默认映射](../../crates/config/src/lib.rs#L591-L603) · [事件规范化](../../crates/macos-adapter/src/lib.rs#L1095-L1103) · [引擎的标志改写](../../crates/rule-engine/src/lib.rs#L904-L920) · [阶段判断](../../crates/rule-engine/src/lib.rs#L1091-L1103) · [注入校验](../../crates/macos-adapter/src/lib.rs#L1552-L1563) · [运行时降级](../../src-tauri/src/lib.rs#L1014-L1037)

### BUG-02 · P1 · 正式发布工作流使用已退役的 runner

正式 arm64 工作流的唯一 job 使用 `runs-on: macos-14`。GitHub 已于 2026-11-02 退役该托管 runner 标签，签名、公证和上传步骤因此无法通过当前工作流开始。应迁移到仍受支持的 arm64 标签，例如 `macos-15`，并用新 runner 验证构建与打包。审查期间核对了官方公告和仓库配置。 [工作流](../../.github/workflows/release-macos.yml#L19-L29) · [项目发布流程](../../docs/release-macos.md#L3-L10) · [GitHub runner 退役公告](https://github.blog/changelog/2026-10-01-github-actions-macos-14-runner-image-retirement/)

### BUG-03 · P2 · 多实例会覆盖设置和剪贴板历史

两个实例使用同一用户目录，各自在启动时读取配置和历史并保留内存副本。设置的写锁和版本号属于当前进程。实例 A 修改设置后，实例 B 可以从旧副本保存另一项设置并覆盖 A 的修改。剪贴板使用同样的快照写回模式。隔离测试用真实 `ClipboardStore` 加载两份历史，A 清空并成功保存后磁盘有 0 条，B 保留原快照并写入一条新的合成文本后，已清空条目重新出现在主文件中。应在读取共享文件前确保只有一个活跃写入者，或在写入时使用跨进程锁和磁盘版本检查。 [共享路径与启动](../../src-tauri/src/lib.rs#L1263-L1268) · [配置初始化](../../src-tauri/src/lib.rs#L1350-L1357) · [设置版本检查](../../src-tauri/src/settings.rs#L87-L119) · [历史加载](../../src-tauri/src/clipboard.rs#L510-L535) · [主文件替换](../../crates/clipboard-core/src/lib.rs#L251-L276)

### BUG-04 · P2 · 自动粘贴可能使用别的内容

选择历史文本后，worker 先写系统剪贴板，再把发送 `Command+V` 排到主线程。底层写入返回剪贴板的 `changeCount`，调用方把它丢弃。派发时只核对目标应用、取消状态和选择代次。用原选择函数和平台替身模拟在主线程调度期间发生后台复制，函数返回成功，替身目标收到的是后台写入的合成文本。应把写入和派发尽量靠拢，保留写入代次，在派发前发现剪贴板已变化时取消。普通系统粘贴还存在事件派发与目标读取之间的间隙。 [写入返回值](../../crates/macos-adapter/src/clipboard.rs#L205-L226) · [返回值被丢弃](../../src-tauri/src/clipboard.rs#L98-L100) · [跨线程派发](../../src-tauri/src/clipboard.rs#L802-L818) · [派发前检查](../../crates/macos-adapter/src/clipboard.rs#L301-L324)

### BUG-05 · P2 · 启动时保留的不可读配置会被后续设置保存覆盖

主配置和备份均无法读取时，例如两份均来自该应用不支持的更高 schema，启动会使用默认值，并显示“原文件保留”。用户随后更改任一设置，首次保存会把原备份替换成旧主配置。第二次保存又会用第一次的默认配置衍生版本覆盖备份。用合成 schema 3、schema 4 文件验证了两次写入的轮换结果，两份原始文件都从原路径消失。应保全无法读取的两份文件，再允许用默认值或新导入内容覆盖正式路径。 [启动回退](../../src-tauri/src/settings.rs#L239-L261) · [设置保存](../../src-tauri/src/settings.rs#L105-L139) · [文件轮换](../../crates/config/src/lib.rs#L838-L865)

### BUG-06 · P2 · 配置落盘后返回失败，重启会采用界面未确认的配置

在临时目录中保留读写均允许的配置文件，再把目录权限设为 `0300`，允许目录所有者写入和查找。通过真实 `save_atomic()` 把活动预设从 `windows_physical` 改成 `custom`，函数返回权限错误，但立即重读主文件已经得到 `custom`。原因是主文件先被原子替换，随后打开父目录同步才报错。设置层收到错误后没有更新内存与版本号，界面仍显示原配置继续生效。应在替换前完成可前置的检查，并让调用方区分替换前失败和替换后同步失败。 [磁盘替换顺序](../../crates/config/src/lib.rs#L838-L865) · [失败后的运行时处理](../../src-tauri/src/settings.rs#L118-L139)

### BUG-07 · P2 · 导入时作用域字段可被静默忽略

在 `keyboard_rules` 内给 B→N 规则填入 `app_bundle_id` 或 `device_identifier`，真实 TOML 导入和桌面校验均通过。键盘、鼠标和全局热键类别会直接编译成 `RuleScope::Global`，校验只按类别检查作用域支持。隔离测试在无应用上下文、以及与规则不同的合成应用上下文中，都观察到 B 转换为 N。设置页还会显示规则里的应用 ID。应在全局类别拒绝携带应用或设备限定字段的启用规则，并明确标出配置路径。 [桌面支持约定](../../README.md#配置与规则) · [规则字段](../../crates/config/src/lib.rs#L20-L38) · [类别校验和编译](../../crates/config/src/lib.rs#L240-L255) · [全局作用域分配](../../crates/config/src/lib.rs#L352-L384) · [设置页标签](../../ui/app.js#L30-L38)

### BUG-08 · P2 · 软件输入进程退出后可能留下影响其他输入的修饰键

一个可识别的软件进程在默认透传模式下发送 Control Down，随后退出且没有发出 Up。应用会为该进程记录已经透传的 Control。来源清理依赖后续收到 PID 和事件标记相同、进程启动时间不同的事件，普通暂停也只释放映射和应用切换生成的持有记录。用真实控制器和合成输入模拟进程退出后再暂停，状态为 `Disabled`，本地键的空修饰标志仍被加上左 Control。应在有可靠退出证据时回收该进程持有的按键，保留其他仍活跃来源各自的持有状态。 [软件来源清理条件](../../src-tauri/src/software_keyboard.rs#L906-L958) · [暂停清理范围](../../src-tauri/src/lib.rs#L790-L815) · [本地透传标志合并](../../src-tauri/src/lib.rs#L429-L446) · [修饰键持有状态](../../src-tauri/src/output_ownership.rs#L124-L147)

### BUG-09 · P2 · Event Tap 启动超时后的迟到成功会锁死模式开关

启动线程若在 3 秒期限刚过后才成功启动 Event Tap，等待方已经设置停止标志。线程无法送达成功结果，运行循环随即退出，清理代码无条件对整个控制器执行 `Shutdown`，使其进入 `Stopped`。之后即使权限齐全，重新点启用也会返回 `runtime has stopped`。应区分本次启动取消与应用级关闭，并允许取消后的下一次正常启动。 [启动超时与清理](../../src-tauri/src/lib.rs#L459-L497) · [停止标志处理](../../crates/macos-adapter/src/lib.rs#L899-L908) · [Shutdown 状态](../../src-tauri/src/lib.rs#L933-L942) · [开关处理](../../src-tauri/src/lib.rs#L1565-L1604)

### BUG-10 · P2 · 剪贴板面板的导航键会被全局映射改写

启用 Windows 模式，添加 `key:36` → `key:11`，即 Enter→B。打开剪贴板面板并用方向键选中记录后，物理 Enter 仍经过全局规则，面板收到 B。真实配置和引擎的合成事件验证了转换，Node 使用真实面板脚本验证 B 不会提交选择，而 Enter 会提交。映射方向键和 Esc 同样会影响面板约定的操作。应在面板聚焦时让面板的操作键使用原生事件，并保证按下和释放走一致的路径。 [Event Tap 分流](../../src-tauri/src/lib.rs#L386-L428) · [全局规则执行](../../src-tauri/src/lib.rs#L989-L1031) · [面板按键处理](../../ui/clipboard.js#L141-L155) · [键盘操作要求](../需求文档.md#L119-L125)

### BUG-11 · P2 · 斜向滚动会漏掉横轴规则

设置 `scroll:horizontal` → `key:3`，以及 `scroll:vertical` → `invert_scroll`。输入纯横轴滚动时，引擎输出完整的 F Down/Up。横轴位移相同、再加上少量纵轴位移时，macOS 适配把主轴定为纵轴，引擎只翻转纵轴，漏掉横轴的 F 动作。当前合并分支只处理翻转和透传。任一轴配置按键替换等其他动作时，会退回只匹配主轴。应对实际有位移的各轴执行已定义的规则，并明确处理单个原生滚轮事件中不同动作的组合。 [轴的选择](../../crates/macos-adapter/src/lib.rs#L1132-L1159) · [轴组合与回退](../../crates/rule-engine/src/lib.rs#L821-L861)

### BUG-12 · P2 · 纯修饰键录出从未同时按下的组合

录制时依次执行左 Control↓、左 Shift↓、左 Control↑、左 Option↓、左 Shift↑、左 Option↑。真实录制脚本生成 `modifier_chord:left_control|left_option|left_shift`，整个过程中三键从未同时按住。引擎在释放前要求当前修饰键集合与规则完全相同，因此重做刚才的手势不会命中这条规则。应记录一次释放前实际同时存在的修饰键集合，或让用户重新录制有歧义的手势。 [录制器](../../ui/rule-editor-core.js#L74-L100) · [引擎匹配](../../crates/rule-engine/src/lib.rs#L194-L207) · [释放时判定](../../crates/rule-engine/src/lib.rs#L727-L743)

### BUG-13 · P2 · 界面成功新增了一条永远选不到的规则

在默认预设新增 `chord:left_control+key:8` → `suppress`。界面固定提交优先级 100，而默认 Ctrl+C 规则优先级为 200。规则编译允许不同优先级的相同触发器，列表同时把两条显示为启用，也没有提示高优先级规则会优先命中。隔离测试验证 Ctrl+C 仍转成 Command+C，关闭默认规则后同一输入才被抑制。应在添加或启用被覆盖的规则时提示冲突，并在界面提供调整优先级或停用现有规则的入口。 [保存优先级](../../ui/app.js#L335-L344) · [默认规则](../../crates/config/src/lib.rs#L620-L624) · [冲突与排序](../../crates/rule-engine/src/lib.rs#L151-L169) · [规则行](../../ui/app.js#L30-L49)

### BUG-14 · P2 · 软件键盘仍可录到转换后的按键

上一轮增加的录制旁路覆盖了本地键盘。可识别的非 Deskflow 软件键盘会在读取录制状态前进入独立路由并提前返回。关闭软件输入透传，启用 Windows 模式并配置 B→N 后，通过这类软件发送成对的 B 事件，录制器会收到转换后的 N。此项核对了原生分流、软件映射与 DOM 录制链路。应让可识别的软件按键流也遵循录制状态，同时保持已有按下与释放配对。 [录制旁路的位置](../../src-tauri/src/lib.rs#L356-L405) · [软件路由](../../src-tauri/src/lib.rs#L611-L642) · [DOM 录制入口](../../ui/app.js#L301-L326)

### BUG-15 · P3 · 本地签名自动检测给 codesign 传错了参数

省略 `CODESIGN_IDENTITY` 时，脚本会把 `security find-identity` 行里的整段 `SHA1 "证书名称"` 作为单个参数交给 `codesign --sign`。本机手册规定可使用完整的 40 位哈希或能匹配的身份名称。Shell 替身捕获到了上述无效参数。有意传入 `CODESIGN_IDENTITY=-` 时，脚本还会接受临时 ad-hoc 签名，与其稳定签名用途冲突。应提取单独的哈希，并拒绝 `-`。 [签名脚本](../../scripts/sign-local-macos-app.sh#L13-L30) · [本地签名约定](../../README.md#本地-macos-构建与权限复用)

### BUG-16 · P3 · 录制器漏了可配置的导航键

真实 Node 录制器对 `Delete`（向前删除）、`Home`、`End`、`PageUp`、`PageDown` 和 `NumpadEnter` 都返回无法识别。Apple SDK 对应的键码依次为 `117`、`115`、`119`、`116`、`121`、`76`，均可通过后端 `key:<number>` 校验。用户可以手填这些值。应补齐录制器的 DOM `code` 对照表。 [前端键表与校验](../../ui/rule-editor-core.js#L6-L19) · [不支持的按键处理](../../ui/rule-editor-core.js#L51-L54) · [后端键码校验](../../crates/config/src/lib.rs#L573-L588) · [键盘需求](../需求文档.md#L43-L54)

### BUG-17 · P3 · 权限恢复后仍显示旧的错误提示

首次检查发现权限缺失时，控制器记录“输入权限未就绪，映射已暂停”。授权后再次检查，运行状态能回到 `Disabled`，但上次的错误字符串仍留在快照中。设置页会同时显示“权限与运行状态已刷新”和旧的权限错误，成功启用模式才会清掉旧错误。应在授权成功时清除对应的权限错误，同时保留其他仍有效的运行故障。 [权限状态转换](../../src-tauri/src/lib.rs#L876-L902) · [设置页提示](../../ui/app.js#L76-L84) · [权限检查响应](../../ui/app.js#L194-L201)
