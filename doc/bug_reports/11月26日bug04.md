## 详细发现

### BUG-01 · P2 · 延迟处理的面板唤起可能记录错误应用

在应用 A 按左 Option+V，趁剪贴板 worker 正在保存或处理其他请求时切到应用 B。入队的 `Show` 只带面板焦点标志，直到 worker 处理命令时才读取前台应用。用真实队列和模拟前台应用验证，A 发起的请求在 B 成为前台后取出，选择条目时目标为 B。后续粘贴还会主动激活并核验已记录的 B，因此原有前台核验无法识别这次目标变更。真实跨应用粘贴待验收。建议在热键触发时绑定相应的应用实例，无法可靠确认发起应用时取消该会话的自动粘贴。 [唤起入队](../../src-tauri/src/clipboard.rs#L533-L548) · [处理唤起时采集](../../src-tauri/src/clipboard.rs#L796-L805) · [使用保存的应用实例粘贴](../../src-tauri/src/clipboard.rs#L891-L931)

### BUG-02 · P2 · 删除或清空请求超时后仍会提交

让剪贴板 worker 两秒内未能处理删除或清空请求。请求已经入队，`request` 等待超时后返回服务不可用。worker 随后仍会取出命令并写入磁盘，回执接收端已经退出。隔离复现使用生产请求 API 和真实存储函数，先观察到清空请求报错，再执行仍在队列里的命令，重读临时文件时历史已清空。删除走同一套请求和执行路径。建议区分尚未开始、正在提交和已经提交，确保超时状态与最终结果可核对。 [删除和清空的请求入口](../../src-tauri/src/clipboard.rs#L600-L606) · [两秒超时](../../src-tauri/src/clipboard.rs#L646-L658) · [执行及回执顺序](../../src-tauri/src/clipboard.rs#L838-L852)

### BUG-03 · P2 · 列表更新使焦点离开删除按钮

用方向键选中一条历史，再用 Tab 聚焦该条目的删除按钮。后台有新剪贴板记录时，面板会重建全部条目，包括仍存在的那条历史的删除按钮，原有焦点元素被移除，条目选择仍保留。接下来按 Enter，若焦点回到页面主体，键盘处理将选择原条目并发起粘贴。Node 隔离测试模拟了被聚焦节点移除后的焦点，观察到 `select_clipboard_item`。原生 WebView 焦点行为待验收。建议按条目 ID 复用节点，或在更新后恢复对应的按钮焦点。 [应用更新并保留选择](../../ui/clipboard.js#L33-L47) · [重建列表和删除按钮](../../ui/clipboard.js#L59-L100) · [Enter 分发](../../ui/clipboard.js#L152-L167)

### BUG-04 · P2 · 交叠按下撤销与重做时，Ctrl+Y 被吞掉

启用 Windows 模式，按住 Ctrl 和 Z，在松开 Z 之前按 Y。运行时发送 Command+Z 的 Down 后，Y 的原始事件和 Command+Shift+Z 的 Down 都被抑制。松开 Z 和 Y 后单独再按 Ctrl+Y，重做的 Down 正常输出。撤销与重做都以同一物理键码 Z 为输出，所有权按键码合并，后到的输出只增加持有者，忽略了两条输出不同的修饰键。建议保留共享目标键的释放保护，并让同一目标键上不同修饰键的快捷键获得各自可见的按下事件。 [默认重做和撤销规则](../../crates/config/src/lib.rs#L21-L33) · [按键输出过滤](../../src-tauri/src/output_ownership.rs#L67-L103) · [按键持有者转换](../../src-tauri/src/output_ownership.rs#L241-L274)

### BUG-05 · P2 · 物理 Alt+Tab 无法保持应用切换器，反向切换丢失 Shift

在默认预设中，用物理左 Command 充当 Windows Alt。按住它再按 Shift+Tab，隔离运行时输出的 Tab Down 只带 Command。该批次还立即释放了合成的 Command，原按键此时仍然按住。普通 Alt+Tab 走同一展开路径。软件输入的快捷键模式已有单独的切换器，可保持 Command 到源 Alt 松开，并为 Tab 保留 Shift。建议物理路径也按 Alt 和 Tab 的按放生命周期控制切换器。应用切换器的实际交互待原生桌面验收。 [默认应用切换规则](../../crates/config/src/lib.rs#L965-L973) · [一次性展开序列](../../crates/macos-adapter/src/lib.rs#L1701-L1715) · [软件切换器](../../src-tauri/src/software_keyboard.rs#L734-L765) · [软件路径启用条件](../../src-tauri/src/software_keyboard.rs#L1335-L1349)

### BUG-06 · P2 · 默认查找快捷键缺失，部分编辑快捷键的 Ctrl 侧别不一致

用三个内置预设分别输入左 Ctrl+F、右 Ctrl+C、双 Ctrl+Z 和双 Ctrl+V，规则引擎均透传。需求将 Ctrl+F 列为默认快捷键，默认规则表没有 F 的命令映射。复制只匹配左 Ctrl。第三轮修复将撤销和粘贴收紧为精确的单侧 Ctrl 组合及其 Shift 变体，也使原本宽松规则能匹配的双 Ctrl 组合失效。建议按同一侧别约定补齐编辑组合，并用预设测试覆盖单侧、双侧和 Shift 变体。 [默认快捷键需求](../需求文档.md#L91-L99) · [默认编辑规则表](../../crates/config/src/lib.rs#L929-L958) · [撤销和粘贴的迁移逻辑](../../crates/config/src/lib.rs#L371-L435)

### BUG-07 · P2 · 预览和刷新传输完整剪贴板原文

剪贴板面板仅显示每条记录的简短预览，但每次创建快照都会复制所有条目的原文。主动刷新还会先发布一次更新事件，再将快照作为 IPC 返回值发送。隔离验证中，一条达到长度限制、每个 Unicode 标量占 4 字节的文本就使序列化快照超过 4 MiB。若 50 条均达到该量级，单份快照的文本约为 200 MiB，另有 JSON 开销。处理耗时和峰值内存待真机量化。建议列表快照只包含 ID、时间和后端生成的预览，粘贴时由 worker 按 ID 读取原文。 [历史容量与长度限制](../../crates/clipboard-core/src/lib.rs#L8-L10) · [快照复制](../../src-tauri/src/clipboard.rs#L219-L230) · [刷新发布更新](../../src-tauri/src/clipboard.rs#L807-L813) · [IPC 返回值](../../src-tauri/src/lib.rs#L2044-L2056) · [预览截断](../../ui/clipboard-core.js#L17-L20)

### BUG-08 · P3 · 修饰键作为输出主键时丢失显式修饰键

导入 `key:96` → `modified:left_command+left_shift`，按 F5。配置接受这条规则，并把 Command 保存为输出标志。引擎处理该修饰键输出时，用从物理输入和现有绑定计算的标志覆盖显式标志。隔离复现只得到左 Shift Down，没有配置中的左 Command。建议定义此类输出的按下和释放语义。若只支持普通键作为带修饰键输出的主键，应在配置校验中明确报错。 [带修饰键输出解析](../../crates/config/src/lib.rs#L787-L793) · [引擎覆盖输出标志](../../crates/rule-engine/src/lib.rs#L1053-L1091)

### BUG-09 · P3 · Caps Lock 录入成功但无法触发映射

录制器会把 Caps Lock 编码为 `key:57`。将其配置为 `key:57` → `key:11` 可以导入和编译。原生 Caps Lock 产生 `FlagsChanged/Changed`，而触发器要求 Down。引擎只为八个左右修饰键推导 Down 或 Up，Caps Lock 不在其中。用对应事件隔离复现得到透传，改为合成的 Down 才匹配。需求约定 Caps Lock 保留原生大小写切换，建议录制器和配置校验提示该触发键不可用。 [录制器键码表](../../ui/rule-editor-core.js#L6-L19) · [默认按下触发](../../crates/config/src/lib.rs#L766-L770) · [原生 FlagsChanged 标准化](../../crates/macos-adapter/src/lib.rs#L1144-L1153) · [引擎阶段转换](../../crates/rule-engine/src/lib.rs#L1198-L1228) · [Caps Lock 产品约定](../需求文档.md#L84-L89)
