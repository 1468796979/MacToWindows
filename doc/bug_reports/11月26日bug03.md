# 11 月 26 日项目 Bug 审查报告 03

审查日期为 2026-11-26（Europe/Zurich）。基线为 `codex/fix-ctrl-s-save` 的 `006f19279a407ea2d80e96f86d5459a2473fbdb9`，包含前两轮修复和 Ctrl+S 修复。本轮核查了默认快捷键、自定义规则、物理与软件输入分流、剪贴板交互及持久化。

## 结论

## 详细发现

### BUG-01 · P2 · 带 Shift 的默认编辑快捷键丢失 Shift

启用任一内置预设，以物理键盘路径输入左 Ctrl+Shift+Z 或左 Ctrl+Shift+V。默认规则用 `chord:left_control+key:6` 和 `chord:left_control+key:9` 匹配，允许额外修饰键，输出却只有 Command。隔离复现中，原始事件被抑制，只输出 `Command+Z` 或 `Command+V` 的按下事件。在以 Command+Shift+Z 重做的应用里，这会触发撤销。支持带 Shift 粘贴变体的应用也会收到普通粘贴。应逐项定义默认规则允许的修饰键，并为需要支持的 Shift 变体保留 Shift。普通用户自定义 `chord:` 的宽松匹配语义可以继续保留。 [默认编辑规则](../../crates/config/src/lib.rs#L773-L802) · [Command 输出](../../crates/config/src/lib.rs#L629-L645) · [组合匹配](../../crates/rule-engine/src/lib.rs#L342-L363) · [Ctrl+S 的精确规则](../../README.md#配置与规则)

### BUG-02 · P2 · 重开仍打开的面板时沿用旧粘贴目标

从应用 A 用左 Option+V 打开面板。面板仍打开时，把焦点切到应用 B，再按左 Option+V 并在面板选择一条历史。窗口的失焦回调只更新键盘旁路标志，worker 的 `panel_open` 仍为真。第二次 `Show` 因而跳过前台应用采集，继续使用 A。选中条目后，自动粘贴路径会主动激活并核验 A，后续检查会确认 A 已成为前台应用。此路径可能把历史文本送到与本次唤起无关的应用。应在外部应用发起新的唤起时重新采集目标，确认面板自身聚焦时如何处理重复唤起。此项基于调用链，待原生窗口交互验收。 [目标采集条件](../../src-tauri/src/clipboard.rs#L635-L658) · [面板失焦回调](../../src-tauri/src/lib.rs#L1552-L1577) · [读取缓存目标](../../src-tauri/src/clipboard.rs#L81-L95) · [恢复目标与粘贴](../../src-tauri/src/clipboard.rs#L770-L819)

### BUG-03 · P2 · 两次选择可能相互取消

一次粘贴失败后，失败原因会留在后续快照的 `operation_error` 中。用户重新选择时，一份仍带旧错误的刷新快照会清除前端的 `selecting`，让第二次 Enter 发出另一个选择请求。Node 隔离复现观察到了两次调用。Rust 队列复现中，请求 B 已取得较新的代次，请求 A 随后收到取消错误。A 的错误处理无条件再递增代次，导致 B 也变成过期请求。应让进行中状态随具体请求结束，且只有仍拥有当前代次的请求才能使其失效。 [前端快照处理](../../ui/clipboard.js#L33-L46) · [选择中的操作保护](../../ui/clipboard.js#L104-L118) · [worker 错误快照](../../src-tauri/src/clipboard.rs#L667-L686) · [代次递增](../../src-tauri/src/clipboard.rs#L453-L463) · [取消检查](../../src-tauri/src/clipboard.rs#L745-L749)

### BUG-04 · P2 · 剪贴板删除和清空的提交结果可能与界面不一致

`save_with_backup` 先替换备份，再替换主文件，最后同步主文件所在目录。若最后一步失败，函数返回错误，worker 保留删除前的内存历史。隔离副本只在主文件替换后模拟最后一次目录同步失败，清空 API 返回错误，但重新读取主文件和从备份恢复所得的历史均已清空。如果备份替换完成后先发生目录同步或主文件替换错误，也存在主文件仍旧、备份已更新的中间状态。应区分替换前失败和替换后的持久性警告，并明确定义双文件写入中断时的恢复规则。设置配置写入已有区分主文件已替换与目录同步失败的处理。 [历史双文件写入](../../crates/clipboard-core/src/lib.rs#L244-L281) · [单文件替换与同步](../../crates/clipboard-core/src/lib.rs#L309-L323) · [失败时保留旧内存历史](../../src-tauri/src/clipboard.rs#L285-L325) · [设置配置的提交结果](../../crates/config/src/lib.rs#L1024-L1044)

### BUG-05 · P2 · 内置剪贴板热键误吞带额外修饰键的组合

按住左 Option 和 Shift、Ctrl 或 Command 中任一个，再按 V。热键只检查左 Option 在按下且右 Option 未按下，在进入规则引擎前即打开面板并截断 V。本地状态机隔离复现中，三种组合的 V Down 和 Up 均被抑制。物理路径在 Windows 模式暂停时也先检查这个独立热键。应在 V Down 上核对完整物理修饰键集合，只锁存有效的左 Option+V，并继续正确处理已经锁存的 V Repeat 和 Up。 [约定的热键](../需求文档.md#42-键盘映射) · [热键匹配及锁存](../../src-tauri/src/lib.rs#L79-L150) · [本地分发顺序](../../src-tauri/src/lib.rs#L1167-L1177) · [软件路径复用热键](../../src-tauri/src/software_keyboard.rs#L1317-L1334)

### BUG-06 · P2 · 自定义剪贴板快捷键遇到队列已满会使全局映射降级

在启用 Windows 模式时配置 `key:96` → `shortcut:show_clipboard`。填满剪贴板 worker 的 32 个队列槽位再触发 F5，隔离复现中 F5 透传，但控制器由 `Running` 进入 `Degraded`，随后 Ctrl+C 也直接透传。原因是规则动作把 `try_show()` 的暂时拒收归为注入错误，沿通用注入失败路径停用映射。内置左 Option+V 在相同拒收条件下已有完整键序列透传逻辑。应把剪贴板队列拒收作为该动作的失败处理，保留其他映射，并测试触发按键的后续重复和释放。 [动作可配置](../../crates/config/src/lib.rs#L718-L729) · [队列与非阻塞入队](../../src-tauri/src/clipboard.rs#L385-L390) · [请求拒收](../../src-tauri/src/clipboard.rs#L445-L447) · [动作错误](../../src-tauri/src/lib.rs#L1267-L1282) · [运行时降级](../../src-tauri/src/lib.rs#L1111-L1127)

### BUG-07 · P2 · 修饰键作为主键的组合匹配依赖输入来源

新增 `chord:left_control+left_shift` → `key:11` 可以通过 TOML 导入与编译。先按左 Ctrl 再按左 Shift，合成的 CoreGraphics `FlagsChanged` 在本地路径只向引擎传入当前侧的 Shift 标志。在可识别软件输入路径，同样的按键顺序传入 Ctrl 与 Shift 的完整状态。用两种标准化结果分别驱动同一份规则，本地事件透传，软件输入产生目标键 Down。应让本地组合匹配读取完整的修饰键集合，同时保持当前侧按下和释放的独立判断。若产品只支持普通键作为 `chord:` 的主键，应在两条路径共同使用的配置校验中给出明确错误。 [触发器解析](../../crates/config/src/lib.rs#L577-L601) · [本地侧别标准化](../../crates/macos-adapter/src/lib.rs#L1305-L1348) · [软件标准化](../../crates/macos-adapter/src/lib.rs#L1023-L1073) · [组合规则匹配](../../crates/rule-engine/src/lib.rs#L342-L363)

### BUG-08 · P2 · 长按会反复执行完整的系统快捷键动作

把 F5 配置为 `shortcut:show_desktop`，再连续送入 F5 Down、Repeat、Up。运行时产生两批调度，Down 和 Repeat 每次都输出完整且相同的 F11 Down 与 Up。在 F11 绑定为显示桌面的系统上，这会反复切换桌面状态。同一分支也会重新调度关闭窗口等系统动作，可能在长按时连续作用到多个窗口。引擎的重复处理会原样复制已经绑定的 `SystemShortcut`。应让显示桌面、关闭窗口等一次性动作每次物理按下只执行一次，并为确实需要连续触发的动作定义单独行为。 [重复事件处理](../../crates/rule-engine/src/lib.rs#L807-L838) · [输出重复规则](../../crates/rule-engine/src/lib.rs#L1228-L1243) · [系统动作展开](../../src-tauri/src/lib.rs#L1283-L1300) · [显示桌面的默认配置](../../crates/config/src/lib.rs#L117-L131)

### BUG-09 · P3 · 滚轮方向配置可保存但无效

需求列出自然和非自然滚动两种预设，TOML 提供 `[mouse].scroll_mode`，默认值为 `non_natural`。隔离复现分别导入 `natural`、`non_natural` 和任意非法字符串，配置均通过；使用内置预设处理同一纵向滚动时，三者均透传。滚动决策只查询预设中的滚轮规则，配置值没有参与规则编译。应明确该字段与逐轴规则的优先关系并接入校验和执行，或在导入时明确报告该字段暂未生效。 [鼠标需求](../需求文档.md#43-鼠标映射) · [配置字段](../../crates/config/src/lib.rs#L85-L101) · [预设编译](../../crates/config/src/lib.rs#L285-L288) · [滚动决策](../../crates/rule-engine/src/lib.rs#L911-L948)
