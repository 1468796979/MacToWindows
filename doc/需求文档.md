# MacToWindows 需求文档 v0.1

## 1. 产品定位

MacToWindows 是一款使用 Rust 开发的 macOS 菜单栏工具，将 macOS 当前的键盘和鼠标操作转换为 Windows 用户熟悉的输入习惯。

目标用户是长期使用 Windows、但需要在 macOS 上工作或开发的个人用户。软件支持全局启停、Windows 预设、规则编辑和紧急恢复。

已确定的首版方向：

- 系统级全局键鼠映射
- 个人自用
- Windows 预设 + 可编辑规则
- Rust 核心 + macOS CoreGraphics 原生适配
- macOS 13+
- Apple Silicon 和 Intel Universal Binary
- 默认按“物理键位”对齐 Windows 键盘
- 暂不支持触控板手势和复杂宏

## 2. 产品目标

### 目标

1. 让 Windows 用户在 macOS 上继续使用熟悉的键位和鼠标习惯。
2. 支持键盘、快捷键、鼠标按键和滚轮的全局转换。
3. 支持一键启用、暂停和恢复 macOS 原生输入。
4. 支持用户编辑、导入和导出映射规则。
5. 映射失败时保持原始输入可用，避免键盘或鼠标被锁死。
6. 提供独立常驻的纯文本剪贴板历史，通过 Win+V 打开并选择后自动粘贴。

### 非目标

- 不修改 macOS 应用内部逻辑。
- 不承诺完全复刻 Windows Shell。
- 不处理登录窗口、FileVault 解锁界面等系统安全界面。
- 不保证 Secure Input、游戏反作弊、虚拟机和远程桌面中的全部输入可重映射。
- 不重排文本字符；输入源切换和 Apple Pinyin 中英文切换通过系统输入源服务处理。
- 剪贴板首版只保存纯文本，不保存图片、文件和富文本。
- 首版不处理触控板手势。

## 3. 默认键位规则

首版 Windows 预设按 Mac 键盘的物理位置对齐 Windows 键盘：

| Mac 物理按键 | Windows 语义 |
|---|---|
| 左 Control | Ctrl |
| 左 Option | Windows |
| 左 Command | Alt |
| 右侧对应修饰键 | 对应 Windows 右侧修饰键 |
| Fn / Globe | 默认透传 |
| 字母、数字、功能键 | 默认保持原键码 |
| Delete、Home、End、Page Up/Down | 提供 Windows 语义预设 |
| 媒体键 | 默认透传，可编辑 |

该映射必须基于物理 keycode 和修饰键状态，而不是仅基于字符。用户可以切换为“快捷键习惯”模式，例如 Command→Ctrl、Option→Alt。

## 4. MVP 功能范围

### 4.1 全局模式控制

- 菜单栏显示当前状态：
  - Windows 模式已启用
  - Windows 模式已暂停
  - 权限不足
  - 事件监听异常
- 支持菜单栏一键启停。
- 支持全局热键启停。
- 关闭后立即恢复原生输入，目标时间不超过 1 秒。
- 提供固定的紧急停用热键，例如物理按键组合 `Control + Option + Command + Esc`。
- 紧急停用热键在映射引擎异常时仍然有效。

### 4.2 键盘映射

支持：

- 单键替换。
- 组合键替换。
- 左右修饰键区分。
- 按下和释放事件分别处理。
- 长按和自动重复。
- 功能键、媒体键、导航键。
- 未配置的按键保持透传。
- 支持一对多和多对一的有限组合映射。
- 防止修饰键卡住、重复触发和事件循环。
- Ctrl+Shift 按 Windows 习惯循环切换当前启用的输入源。
- Caps Lock 保留为原生大小写锁定；首次使用需关闭 macOS 的 Caps Lock 输入源切换选项。
- Apple Pinyin 中独立按 Shift 切换中英文，Shift+字母和长按行为保持原生。
- 左 Option+V 作为 Windows Win+V，打开本地剪贴板历史；选择条目后恢复原应用并自动粘贴。

默认提供常用快捷键规则：

- Ctrl+C / V / X / Z / A / F / S
- Alt+Tab
- Win+L
- Win+D
- Win+E
- Win+Shift+S
- 窗口关闭、应用切换、锁屏等动作

macOS 没有直接等价动作时，界面必须明确标记为“不支持”或“需自定义”，不能静默吞掉输入。

### 4.3 鼠标映射

MVP 支持：

- 左键、右键、中键。
- 侧键和额外按钮。
- 垂直滚轮方向。
- 水平滚动方向。
- 鼠标按下、释放和拖拽状态。
- 鼠标移动默认透传。
- 多显示器坐标保持 macOS 原生行为。
- 支持自然滚动和非自然滚动两种预设。

触控板手势、鼠标加速度曲线和复杂鼠标宏放入后续版本。

### 4.4 剪贴板历史

- 剪贴板采集和 Win+V 不受 Windows 模式启停影响，应用启动后独立运行。
- 只保存非空纯文本，最多保存 50 条；单条超过 1,048,576 个 Unicode 标量值时跳过。
- 相同文本再次复制时移到最前并更新时间。
- 历史保存到 `~/Library/Application Support/MacToWindows/clipboard-history.json`，使用本地 JSON 原子写入。
- Win+V 面板支持鼠标选择、上下键、Enter、Esc、删除单条和清空全部历史。
- 选择历史后写回系统剪贴板、恢复打开面板前的应用并注入一次 Command+V；恢复失败时不向当前错误窗口粘贴。

### 4.4 配置中心

配置界面需要提供：

- 当前配置预设。
- 可搜索的映射表。
- “录制按键”功能。
- 修改输入和输出。
- 单条规则启用/禁用。
- 恢复单条默认规则。
- 恢复整套默认配置。
- 导入配置。
- 导出配置。
- 冲突检测。
- 循环映射检测。
- 权限状态和诊断信息。

建议采用版本化 TOML 或 JSON 配置格式，并使用原子写入，避免配置损坏。

配置至少包含：

```text
schema_version
active_profile
keyboard_rules
mouse_rules
global_hotkeys
app_rules
device_rules
```

首版只启用全局规则；按应用和按设备配置作为后续扩展。

## 5. 用户流程

### 首次启动

1. 显示产品用途和隐私说明。
2. 说明软件需要读取和控制键盘、鼠标输入。
3. 检查 Accessibility、Input Monitoring 和 Post Event 权限。
4. 引导用户打开系统设置。
5. 用户完成授权后重新检测。
6. 提供测试按钮，验证键盘和鼠标事件是否正常。
7. 默认进入 Windows 预设，但不自动拦截，直到用户主动启用。

macOS 的事件监听和事件注入依赖 CoreGraphics 事件接口，例如 [`CGEventTapCreate`](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate%28tap%3Aplace%3Aoptions%3Aeventsofinterest%3Acallback%3Auserinfo%3A%29)、[`CGEventTapPostEvent`](https://developer.apple.com/documentation/coregraphics/cgevent/tappostevent%28_%3A%29)、[`CGPreflightListenEventAccess`](https://developer.apple.com/documentation/coregraphics/cgpreflightlisteneventaccess%28%29) 和 [`CGPreflightPostEventAccess`](https://developer.apple.com/documentation/coregraphics/cgpreflightposteventaccess%28%29)。

### 日常使用

1. 用户登录 macOS。
2. 应用作为菜单栏后台进程启动。
3. 用户选择 Windows 模式。
4. 键鼠事件按照当前规则转换。
5. 用户可以随时暂停或恢复原生模式。

### 权限不足

- 不拦截原始事件。
- 不注入替代事件。
- 菜单栏显示明确状态。
- 提供重新检测和打开系统设置按钮。
- 权限被撤销后进入安全降级模式。

## 6. 推荐技术架构

```text
macOS Event Adapter
        ↓
Rust Event Normalizer
        ↓
Rust Rule Engine
        ↓
Decision: Pass / Suppress / Emit
        ↓
macOS Event Injector
        ↓
系统事件流
```

核心模块：

- `macos_adapter`
  - 创建和管理 `CGEventTap`
  - 监听键盘、鼠标事件
  - 注入替换事件
  - 处理权限、RunLoop 和事件 Tap 重启
- `event_model`
  - 统一键盘、鼠标、修饰键和时间戳模型
- `rule_engine`
  - 纯 Rust 实现
  - 可独立进行单元测试
- `config`
  - 配置读取、校验、导入、导出和原子写入
- `tray_ui`
  - 菜单栏界面和设置窗口
- `diagnostics`
  - 权限、事件 Tap、配置和性能诊断

建议的内部接口：

```text
Event {
    device,
    kind,
    phase,
    key_code,
    mouse_button,
    modifiers,
    location,
    timestamp
}

Decision {
    Pass,
    Suppress,
    Emit(Vec<NormalizedEvent>)
}
```

注入事件必须写入唯一标记，避免软件再次捕获自己生成的事件，形成无限循环。

## 7. 故障与安全要求

- 规则引擎异常时，原始事件必须透传。
- 注入失败时，不得持续吞掉原事件。
- 应用退出或崩溃前，尽可能释放所有已按下的虚拟按键。
- 检测 `CGEventTap` 被系统禁用，并尝试自动恢复。
- 事件回调中禁止执行阻塞 I/O。
- 不记录用户输入的原始文本。
- 默认不记录具体按键内容，只记录事件类型、错误和性能指标。
- 日志支持关闭。
- 配置文件只允许本地访问。
- 不依赖 root 权限。

## 8. 非功能需求

### 性能

- 事件处理延迟 P95 小于 5ms。
- 用户可感知的端到端延迟目标小于 20ms。
- 空闲 CPU 使用率低于 2%。
- 常驻内存目标低于 100MB。
- 规则数量增加后，延迟不能明显增长。

### 兼容性

必须测试：

- Apple Silicon。
- Intel Mac。
- ANSI、ISO、JIS 键盘布局。
- 内置键盘和外接键盘。
- 多显示器。
- 外接鼠标和不同按钮数量的鼠标。
- 睡眠、唤醒和设备热插拔。
- Finder。
- Safari 或 Chrome。
- TextEdit。
- Terminal。
- VS Code。
- 中文输入法和英文输入法。

以下场景标记为兼容性限制：

- Secure Input。
- 登录窗口和系统安全界面。
- 游戏反作弊。
- 虚拟机。
- 远程桌面。
- 部分全屏应用。

## 9. 验收标准

### 功能验收

- Windows 模式可以通过菜单栏和热键启停。
- 启停无需重启应用。
- 未配置按键 100% 透传。
- 默认键位规则按物理键位正确转换。
- 常用快捷键在 Finder、浏览器、编辑器和终端中可用。
- 鼠标按钮、滚轮和拖拽不出现明显卡顿。
- 导入导出配置后，规则结果一致。
- 配置重启后仍然保留。
- 权限不足时不会吞掉输入。
- 紧急停用始终有效。

### 稳定性验收

- 连续执行随机按键和鼠标操作，不出现重复键、丢键或卡键。
- 连续运行 8 小时无明显内存增长。
- 事件 Tap 被系统禁用后可以提示并恢复。
- 应用异常退出后不会留下持续按下的虚拟修饰键。
- 外接设备断开和重连后可以继续工作。

### 测试方式

- Rust 规则引擎单元测试。
- 修饰键状态机测试。
- 随机事件序列测试。
- macOS 真机集成测试。
- 多键盘布局测试。
- 权限撤销和恢复测试。
- 睡眠唤醒测试。
- 手工兼容性回归测试。
